## Goal of this slice

The room built in M24.1 is lit only by the board shader's single directional key, so it
looks flat and like daylight. After this slice:
- the room is lit by up to **8 local lights** that exist as objects in the room:
  - a dim ceiling panel;
  - an LED strip under the shelf above the bench;
  - the task lamp;
  - the projector's glow;
  - the magazine's bay LEDs;
  - moonlight through the skylight;
- the directional key is turned almost off in the lab, so those lights carry the
  picture;
- the skylight shows a night sky with stars at infinity: they don't move with
  translation, only with rotation;
- a `roomLight` setting scales the room's practical lights (not the machine's).

Still **not** in this slice: the board in the lab, slab lights and focus mode (all M24.5);
the projector hologram (M24.3); camera moves (M24.4a).

**Pixel-exactness rule:** with the lab off, every frame must be byte-identical to before.
The light buffer then holds zero lights and a key factor of exactly 1.0, and the shader
must take a path that adds exactly zero. Test it (Step 6).

## Step 2 — the falloff, as one pure function shared with the shader

Create `src/render/lab_light.{hpp,cpp}`:

```cpp
namespace cb::render {

/// One light in the renderer's world (cells), as uploaded. 48 bytes: three vec4s.
struct GpuLight {
  float posRadius[4];     ///< xyz world position, w = radius in metres
  float colorIntensity[4];///< linear rgb, w = intensity
  float dirCone[4];       ///< xyz unit direction (spot) or 0, w = cos(cone)  (point: w = -2)
  // The spot's soft edge: cos(cone + soft) goes in the header's per-light slot (see below)
};
static_assert(sizeof(GpuLight) == 48);

/// The block the board shader reads at set 0, binding 1.
struct GpuLightBlock {
  float header[4];        ///< x = light count (0..8), y = key factor, z = metres per world unit, w = 0
  float softCos[8];       ///< per light: cos(cone + soft); unused for points
  GpuLight lights[8];
};

/// Distance attenuation, `dm` and `radius` in metres. Exactly 0 at dm >= radius.
[[nodiscard]] float lightFalloff(float dm, float radius) noexcept;
/// Spot cone factor: 1 inside cos(cone), 0 outside cos(cone+soft), smoothstep between.
[[nodiscard]] float spotFactor(float cosAngle, float cosCone, float cosSoft) noexcept;

/// Build the block from the lab's lights; roomLight scales group "room".
[[nodiscard]] GpuLightBlock labLightBlock(const io::LabDoc& doc, const LabScene& scene,
                                          float roomLight, float keyFactor);
/// The neutral block: no lights, key factor 1. What the renderer uploads with the lab off.
[[nodiscard]] GpuLightBlock neutralLightBlock() noexcept;

}  // namespace cb::render
```

The falloff (write it identically in C++ and GLSL):
```
x   = dm / radius
win = clamp(1 - x^4, 0, 1)^2        // smooth window, exactly 0 at the radius
att = win / (dm*dm + 0.25)          // inverse-square, softened so it is finite at 0
```
The spot factor is `smoothstep(cosSoft, cosCone, cosAngle)`, with `cosAngle = dot(-L, dir)`,
where `L` is the unit vector from the fragment to the light.

The GLSL `std430` layout of the block must match `GpuLightBlock` exactly. With `std430`,
a `float softCos[8]` array has a 4-byte stride, so it matches the C++ array. Add a
`static_assert(sizeof(GpuLightBlock) == 16 + 32 + 8*48)`, and an `offsetof` assert for
`lights`, which must be 48.

**Tests** (`tests/render/test_lab_light.cpp`, `[unit][render][light]`):
- `lightFalloff(radius, radius) == 0` and `lightFalloff(radius * 1.5, radius) == 0`;
- the falloff is monotonic non-increasing on [0, radius] in 100 steps;
- `lightFalloff(0, r) == 4` (1 / 0.25);
- `spotFactor` is 1 inside the core, 0 outside the soft edge, and monotonic between;
- `labLightBlock`:
  - the count equals the doc's lights;
  - positions are converted with `LabScene::toWorld`;
  - a `room` light's intensity is × `roomLight`, and a `machine` light's is unchanged;
  - `header.z == 1 / kCellsPerMetre`;
- `neutralLightBlock()` has a count of 0 and a key factor of exactly 1.0f.

## Step 4 — the shader (`src/render/shaders/board.frag`)

1. Declare the block:
   ```glsl
   struct Light { vec4 posRadius; vec4 colorIntensity; vec4 dirCone; };
   layout(std140, set = 0, binding = 1) uniform LightBlock {
       vec4 header;      // x count, y key factor, z metres per world unit
       vec4 softCos[2];  // 8 floats packed as 2 vec4 (std140 arrays of float have a 16-byte stride!)
       Light lights[8];
   } lightBuf;
   ```
   A uniform buffer uses **std140**, where `float softCos[8]` would have a 16-byte stride.
   So in GLSL declare it as `vec4 softCos[2]` and read element `i` as
   `softCos[i / 4][i % 4]`. The C++ `float softCos[8]` is 32 contiguous bytes, which
   matches `vec4[2]`. `Light` is three vec4s, which is fine in std140.
2. **The key factor.** Find the line
   `vec3 shade = mix(cool * 0.52, warm, lambert);` (around line 223). Directly after it,
   add:
   ```glsl
   shade *= lightBuf.header.y;   // 1.0 outside the lab: unchanged
   ```
   Multiplying by exactly 1.0 is exact in IEEE floats, so frames with the lab off stay
   byte-identical.
3. **The local lights.** After `vec3 rgb = fragColor.rgb * shade;`, add:
   ```glsl
   int lightCount = int(lightBuf.header.x + 0.5);
   if (lightCount > 0) {
       vec3 sum = vec3(0.0);
       vec3 toEye = normalize(push.eyePos.xyz - fragWorld);
       for (int i = 0; i < lightCount; ++i) {
           Light L = lightBuf.lights[i];
           vec3 d = L.posRadius.xyz - fragWorld;
           float dist = length(d);
           vec3 l = d / max(dist, 1e-4);
           float dm = dist * lightBuf.header.z;
           float x = dm / L.posRadius.w;
           float win = clamp(1.0 - x*x*x*x, 0.0, 1.0);
           float att = win * win / (dm * dm + 0.25);
           if (L.dirCone.w > -1.5) {   // spot
               float cosA = dot(-l, L.dirCone.xyz);
               att *= smoothstep(lightBuf.softCos[i / 4][i % 4], L.dirCone.w, cosA);
           }
           float ndl = max(dot(n, l), 0.0);
           vec3 h = normalize(l + toEye);
           float spec = pow(max(dot(n, h), 0.0), 32.0) * 0.25;
           sum += L.colorIntensity.rgb * L.colorIntensity.w * att * (ndl + spec);
       }
       rgb += fragColor.rgb * sum;
   }
   ```
   The `if (lightCount > 0)` guard is what keeps the lab-off path exact.
4. **Emitters are not lit.** The glow (5), hologram (4) and LED (7) materials emit their
   own light. Apply the local lights only when `matId` is 0, 1, 2, 3 or 6. Wrap the
   block above in that test. Leave LED cells alone even in later slices: their look is
   tuned (M23.9).
5. **Metal (matId 1).** Read its branch (around line 510). It uses `push.lightDir` for its
   highlight. Leave it as it is: the key factor already dims its base shade, and the
   local `spec` term above adds the lamp highlights.
6. Recompile. Shaders build through `glslc` in `src/render/CMakeLists.txt`; nothing to
   register, because `board.frag` is already listed.

## Step 5 — the sky through the skylight

1. Add a material `sky` to the lab file's `material` values. Map it to a new shader
   material id **8**. Grep `shaderMaterial` and `view::Material` (in
   `src/view/theme.hpp`) to see how ids are assigned, and add `Material::Sky` at the
   end of the enum with id 8. **Check that no existing code switches over
   `view::Material` exhaustively** without a default. If one does, add the case there
   (as matte).
2. In `board.frag`, before the generic shading branches, add:
   ```glsl
   if (matId == 8) {
       // The night sky through the skylight: stars at infinity (only the view direction
       // matters, so they do not slide as the camera moves), a faint city glow at the
       // horizon side, and nothing else.
       vec3 v = normalize(fragWorld - push.eyePos.xyz);
       vec3 sky = vec3(0.010, 0.012, 0.022);
       // three octaves of hashed star cells on the direction
       for (int o = 0; o < 3; ++o) {
           float scale = 140.0 * pow(2.1, float(o));
           vec3 p = v * scale;
           vec3 cell = floor(p);
           float h = hash13(cell + float(o) * 17.0);
           if (h > 0.985) {
               vec3 c = cell + 0.5 + 0.35 * (vec3(hash13(cell + 1.3), hash13(cell + 2.7),
                                                   hash13(cell + 4.1)) - 0.5);
               float dd = length(p - c);
               float tw = 0.75 + 0.25 * sin(push.visual.x * (1.0 + 3.0 * h) + h * 40.0);
               sky += vec3(0.85, 0.9, 1.0) * smoothstep(0.22, 0.0, dd) * (h - 0.985) * 60.0 * tw;
           }
       }
       sky += vec3(0.05, 0.03, 0.02) * smoothstep(0.2, -0.3, v.y);  // city glow toward -Y
       outColor = vec4(sky, 1.0);
       return;
   }
   ```
   - **Check** what `push.visual.x` holds (grep `visual` in `board_renderer.cpp` where the
     push constants are filled). If it is not the visual time in seconds, use the
     component that is, and note it.
   - **Check** that `hash13` exists with that signature in `board.frag` (it does at
     around line 57; confirm).
   - **Check** how `outColor` is written at the end of `main()` (fog, HDR scale, dither).
     If the scene writes HDR values with some scale, follow it. Simplest: compute `sky`,
     assign it to `rgb`, and jump to the end the way other early-outs do, if any exist.
     If there is no early-out pattern, set `rgb = sky` and skip the lighting with a flag.
3. Change `skylight.glass` in `assets/lab/lab.toml` to `material = "sky"`.

## Pitfalls

- **std140 vs std430.** Uniform buffers use std140, where arrays of scalars have a 16-byte
  stride. That is why `softCos` is two vec4 on the GLSL side. Get this wrong and the
  spots will have random cones.
- **The pipeline layout** must be recreated with the new set layout. Everything that
  creates the board pipeline (grep `fxSetLayout_`) uses the one layout, so changing the
  set layout covers it. Check the blend pipeline and the shadow pipeline too: they share
  `layout_`.
- **lavapipe** is slow with loops in fragment shaders. Keep the loop bound at
  `lightCount`, not 8.


## Status

**2026-11-12 — built.** Added the validated `[[light]]` schema and seven authored
practicals, metre-space falloff and cone helpers, the packed 432-byte light block,
per-frame uniform buffers at binding 1, and the local Lambert/Blinn lighting in the
existing board pipeline. `roomLight` / `room_light` is persisted and clamped to finite
0..2; `--room-light` overrides it for one run. Machine lights retain their authored
intensity. `lights` reaches the loaded document through the GUI's console setter and
needs no game. The lab-off path uploads the neutral block every frame.

The skylight uses material `sky` / `Material::Sky` (shader id 8), with direction-space
stars and city glow. `push.visual[0]` is the existing presentation time in seconds,
modulo 120. The sky uses the common final `rgb` write: this shader has no final fog,
dither or HDR scale to duplicate. All existing material switches were checked; none
required an additional exhaustive-switch case. Light hex colours decode sRGB to
linear; authored linear triples and the existing part-colour convention are preserved.

Tuning and small deviations:
- Ceiling intensity is **8.0**, and moon intensity **1.2**, rather than the starting
  0.35 / 0.30. Reviewed comparisons showed that the original values lost the walls and
