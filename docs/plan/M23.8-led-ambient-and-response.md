# M23.8 — Quiet LED interference and LCD colour response

Status: checkpoint A implemented; checkpoint B pending. This follows M23.7 and
is requested work, distinct from the unselected options in `visual_ideas.md`.

## Intended result

A Manifold board should feel like a bank of powered display panels carrying
holographic pieces. Occasionally a small strip *inside one square* changes
brightness almost imperceptibly and recovers. When gameplay actually changes a
square's displayed colour, its panel gives a very small LCD overdrive/settling
response. Neither effect moves a piece, displaces a square, obscures a move cue,
changes a portal hue or makes the entire board pulse.

Use existing opaque cell geometry and the existing explicit presentation clock.
No extra render pass, textures, bloom, transparency system, gameplay timer or RNG
state. Console, matte captures, the glass plinth, tokens and holograms retain their
current behaviour. These are display effects, never engine or replay data.

## Findings from the actual implementation

- `board.frag`, material 7, currently draws a **static** cell-local emitter matrix,
  dark face border and unlit sidewall. `panelPitch` derivatives filter the matrix
  when distant. Time currently affects holograms, not this LED branch.
- `BoardRenderer::setVisualTime` sanitizes explicit seconds. `record` writes their
  modulo-120 value to `Push::visual.x`; GUI interactive and capture paths already
  set this clock. Reuse it. `--t` remains overture position.
- Flat cells receive colours in `BoardRenderer::buildInstances` around the
  `pl.cell == p.selected()` branch. Geometry cells receive colours through that
  function's `fillFor` lambda. Both choose parity, selection, legal empty/capture
  destinations, peek destinations, last-move marks, attacker/defender/path hints,
  then pointer hover. **These actual resolved colour changes** are the LCD triggers.
  A moving piece alone is not an invented panel-colour event.
- `withHover` blends toward white. `withHint` applies existing semantic tints.
  Preserve their current order, weights, alpha and option predicates exactly.
- Geometry cells are vertex-coloured patches in one identity instance. Its material
  is uniformly 7. A material fractional seed or instance ID cannot distinguish
  those cells. Existing `MeshVertex::panelCoord` supplies patch UVs, including slide
  and inversion, and must remain dedicated to that contract.
- `buildInstances` is documented `const`, pure and side-effect free. It cannot
  silently remember old colours or read wall time. Existing material tests supply
  independent snapshots and isolated meshes. True colour-change response needs
  an explicitly owned presentation history; a time-only shader cannot infer it.

The nearest patterns to extend are the LED branch/UV transport from M23.4B, the
explicit time route from M23.4A, and the existing instance/surface construction in
`board_renderer.cpp`. Extend those paths rather than adding a screen-space overlay.

## A. Sparse ambient interference

### Identity and GPU payload

Add a zero-initialized `float panelSignal[3]` to `MeshVertex` and `Instance`:
`{seed, responseGain, effectWeight}`. Update their size assertions, vertex attribute
descriptions and matching GLSL declarations together. Locations 13 (mesh) and 14
(instance) are available in the present pipeline; use `R32G32B32_SFLOAT`, binding
0/1 respectively. Verify device vertex-input limits normally; no new binding.
The vertex shader forwards the sum as a new `vec3` varying, location 11. Existing
non-panel data remains all zero. Never steal alpha, seam masks or material ids.

- Flat slab meshes contain zero signal; each real LED cell instance carries it.
- Sampled surface vertices carry it; their identity instance contains zero signal.
- Exactly one source is nonzero. Seed and gain are constant on all vertices of one
  patch. Weight may attenuate toward seam vertices and can interpolate.
- Seed is derived from `CellId` alone using a documented fixed integer hash:
  `(1 + hash(cell) % 65535) / 65536.0f`. Zero means effects disabled, useful for the
  existing synthetic steady LED fixture. Do not hash position, camera, parity,
  colour, mesh subdivision, instance ordering or frame count. Equal cells retain
  their phase between flat/shape view, slides and inversion. Distinct IDs may hash
  collide; uniqueness is unnecessary.
- Face weight is 1 on ordinary panel faces. Geometry rail-coloured vertices get
  weight `1 - clamp(max(ru.weight,rv.weight),0,1)` using the *already computed*
  rail blend, never another gluing calculation. Fully coloured portal rails are
  unchanged; partial blends receive less effect. Sidewalls are excluded in shader.
  Flat portal rails are separate non-LED instances and remain unchanged.

An extra 12 bytes per instance and vertex is deliberate and bounded; record the
new sizes. Do not add per-frame allocations proportional to screen pixels.

### Shader behaviour and initial constants

Apply inside material 7 **after** the existing LED base calculation, only when
seed > 0 and `fragPanel.z >= 0.5`. Keep the emitter derivative calculations outside
any divergent branch, as they are now. Reuse the existing `undersampled` factor to
fade effects away before a tile becomes a few pixels. This is not additional noise
on subpixel geometry.

Use an integer hash in GLSL, seeded from the exactly represented 16-bit seed and
`floor(push.visual.x / 12)`. One 12-second epoch has either zero or one event for
that cell; admit approximately one third of seeds per epoch. The event's start
lies between 0.5 and 11.0 seconds, with duration 0.28 seconds. Hash independent
lanes for start and rectangle, not successive floating sine calls. A smooth
0.06-second fade in/out prevents a hard flash. At the 120-second clock wrap all
events are already off, so there is no board-wide discontinuity.

The disturbance is one UV rectangle, width 0.18–0.35 and height 0.025–0.055, wholly
inside [0.15,0.85]². Snap its short edges to the existing emitter-row grid where
possible. A feathered edge of roughly one emitter row is sufficient. Slightly
attenuate its luminance, with optional immediately adjacent half-strength brighter
strip; **total maximum local RGB multiplier departure is 0.028**. No hue rotation,
channel split, displaced geometry, lost pixels, text or sparkles. At most one
rectangle per cell, no looping noise octaves.

Multiply amplitude by effectWeight, the interior mask and `1-undersampled`.
This gives roughly one or two tiny events per second across a standard board,
with substantially fewer than one affected cell on average. The spatial footprint
is small enough that ordinary play should not call attention to it. The geometry
may be huge: do not try to enforce a globally synchronized “only one cell” budget.
Sampling fewer visible cells naturally reduces the number of perceptible events.

## B. Actual colour-change response, without hidden renderer history

### Explicit state and pure construction

Introduce a small presentation helper in `src/render/panel_response.hpp/.cpp`,
registered in `src/render/CMakeLists.txt`, with tests in
`tests/render/test_panel_response.cpp`. The GUI owns one helper for its current
interactive board. It uses explicit `double` seconds and a caller-supplied reset;
it never reads SDL, ImGui time, the engine clock or an address as a random seed.

Make `buildInstances` optionally report its resolved panel targets and payload
locations through an output collector. Existing callers default to no collector
and pay no metadata allocation. A record contains:

- logical `CellId` and final **pre-material, pre-rail** target `view::Rgba`;
- either a final flat instance index or a surface vertex range;
- enough tagging to distinguish those two destinations safely.

Report after instance batching has resolved final indices. Surface ranges include
all of the corresponding patch's vertices; multiple patches can share a CellId.
Observe each distinct cell once, then apply its same gain to all destinations.
Do not use the geometry identity instance as a target. Keep the existing two fill
paths semantically identical; factoring their common fill decision into a local
pure helper is appropriate if it avoids divergence, but is not a rules rewrite.
Do not build the whole board twice to discover colours.

The helper owns `{lastTarget, changedAt, initialized}` per observed CellId.
A target change is a maximum RGB-channel difference greater than 1/255; alpha-only
changes do not trigger. Initial observation is settled (gain zero), preventing a
whole-board flash on startup. No-change observations do not restart the timer.
A new meaningful colour change restarts it; no accumulating intensity. Invisible
cells are discarded from history so newly visible boards start settled, rather
than reviving an old colour event. Repeated same-time observations are idempotent.

For elapsed time `a` in [0,0.24), response gain is
`0.018 * (1 - smoothstep(0,0.24,a))`; otherwise zero. The new semantic colour is
visible **immediately**, with at most 1.8% overdrive settling toward it. Do not
blend in the old capture/selection colour for 240ms: a removed legal cue must
actually disappear. This is luminance settling, not a claimed physical LCD model.

Apply the gain to payloads after pure construction and before recording. The LED
shader adds this small gain to its multiplier, weighted by the same interior,
rail and distance suppression as ambient interference. Combined ambient+response
must be clamped to a maximum 0.04 multiplier departure. Alpha is untouched.

### Lifetime and GUI integration

In interactive `src/gui/main.cpp`, request the optional collector for the ordinary
board build near the existing `syncMarks`/`advanceAnimation`/`buildInstances` path.
Observe/apply immediately using that frame's existing `visualSeconds`. Do not feed
trailer/decorative/overture instances into it. Reset on session replacement/new
load, theme/material change, view-layout/parity option change, and clock rewind.
Switching geometry presentation may simply reset settled; it must not cause a
burst. A camera orbit, object translation or repeated redraw is not a reset or
colour event. Non-LED themes skip the helper entirely.

Normal pause can let elapsed presentation time settle while the board is blurred;
resuming must not restart responses. The explicit helper clock retains full
precision; only the ambient shader clock wraps at 120 seconds.

### Concrete reset contract after API investigation

There is no existing session revision/reset marker. Neither `game().plyCount()`
nor the position hash distinguishes a legitimate move from a replacement, and
neither catches reloading an identical position. Do not infer resets from these.

Add `std::uint64_t presentationEpoch_{0}` and a const/noexcept
`Session::presentationEpoch()` accessor in `src/app/session.hpp`. It identifies
**discontinuities**, not every snapshot refresh; it has no renderer dependency,
never enters serialization/hashes and contains no clock. Increment only here in
`src/app/session.cpp`:

1. `Session::loadFen`: after parsing succeeds and the new Game/position replaces
   the old one, before returning the refreshed snapshot. Bad FEN leaves the epoch
   unchanged. Reloading the identical valid FEN still increments it.
2. `Session::apply`, `ActionKind::Reset`: after `game_->reset()`. Reset at the
   opening position still increments it. Ordinary Undo does **not** increment it:
   removing/replacing last-move and selection colours should respond normally.
3. `Session::loadGame`: after the existing cheap mismatched-variant-name rejection,
   immediately **before** calling `applyGameFile`. Increment on every such import
   attempt, not just success. `src/io/game_file.cpp::applyGameFile` sets the start
   position and plays moves progressively, and can then fail at an illegal move.
   A failed import can therefore have mutated the Game. Conservative invalidation
   on a same-variant attempt that fails earlier is harmless and deliberate. Do not
   change import atomicity or stale-snapshot error behaviour in this visual slice.

No other mutation points are necessary: `GameRunner::reset()` calls `loadFen`, so
`startWatching` and `watchSeek` inherit the discontinuity automatically, including
seeks that later fail. Ordinary `GameRunner::step`/`Session::playMoveText` do not.
`src/app/debug_console.cpp` routes `setfen` and its `place`/`remove`/`side` commands
through `loadFen`, including when the console executes inside `Ui::build`. Thus
there is no need for a special UiRequest or console-parser interception.

The interactive GUI compares `(Session*, presentationEpoch)` **immediately before
its normal board build**, after Ui::build and request processing. `Shell::startGame`
constructs a new Session while the previous one still exists, then replaces it;
the pointer detects the normal replacement, and the counter catches same-Session
loads. Keep no dereferenceable old Session pointer in the helper: the GUI only
compares identity values, clears history on change, and remembers the current pair.
Clear remembered identity whenever there is no ordinary board/session or the
renderer is drawing an attract/overture source. If future code can replace a
Session multiple times without an intervening observation, its replacement sites
must explicitly invalidate this GUI history rather than relying on pointer reuse.

Keep a small explicit GUI presentation key alongside it: resolved theme identity,
`BoardOptions::flat`, `surface`, `swapLayerColors`, `showLegalMoves`, `showLastMove`,
and `ViewConfig`'s screen-axis selection/layout orientation. Compare named fields,
not raw struct bytes/padding. Those changes clear history and baseline the newly
resolved targets. A palette settings change that alters resolved theme colours
also clears history. Continuous `surfaceSlideU/V`, `surfaceEvert`, `surfaceFormed`,
hyper rotations, camera movement, blur and alpha are excluded; they must not
perpetually reset a response while a surface animates. Piece-only options do not
reset cell history. New semantic hints/hover/peek are real target changes rather
than reset triggers. Clock rewind independently resets the helper.

Test these boundaries before adding production lines:

- Extend `tests/unit/app/test_session.cpp`: epoch changes for identical valid FEN,
  successful reset/import and a partially invalid same-variant move list; unchanged
  after invalid FEN, cheap mismatched-name rejection, normal legal move, undo,
  selection, hover, orbit and `refreshSnapshot` via ordinary frame activity.
- Extend existing `test_debug_console.cpp` cases through the real command entry
  for `setfen` and one edit command: same Session address, changed epoch. Do not
  simulate these solely as a UiRequest, which is the original blind spot.
- Extend `test_game_runner.cpp`: reset/seek changes the epoch, ordinary step does
  not. Existing watch error paths remain unchanged.
- In a GUI/offscreen integration fixture, establish an active colour response,
  reload the same variant/FEN through the real APIs, observe the next build, and
  require settled gain. Then make/undo a normal move and require the relevant
  changed colours to respond. Include console replacement executed during Ui
  build so the identity check's placement is actually tested.

These additions touch L95 app and L110 GUI, never engine layers. Run app tests as
well as render tests for checkpoint B. The epoch's only invariant is change versus
no change, not its serialized value; uint64 wrap is immaterial over a session's
practical lifetime. Draft ADR-0024 records the new presentation-history boundary
and payload without editing accepted ADR-0021/22/23. Add it to the ADR index when
accepting the implementation; its capture limitation is part of the decision.

### Concrete helper API (Astra follow-up)

Use `PanelResponse::prepare(const app::Session*, const view::Theme&, const
BoardOptions&)` to compare the named reset fields centrally and return whether
LED target collection is needed. A null source clears it. `apply(InstanceSet&,
std::span<const PanelTarget>, double)` owns observations and explicit-time rewind;
`clear()` discards both source identity and history. The GUI invokes prepare after
UI/request handling; the helper stores the old Session address only as an opaque
identity value and never dereferences it later. Tests can use apply directly for
an isolated event sequence. Compare six target palette arrays (dark/light, ember,
moss, blood, peek), cell material, the named options and screen/grid axis lists
and orientation. No raw Theme/option byte comparisons.

### Capture limitation and honest fallback

Independent `--shot`/`--clip` captures currently reconstruct snapshots without a
shared colour-event history. Feeding their warmup frames to this tracker would
make extra renders or sampling order change the image and break M23.5's still/clip
agreement. **Default capture paths therefore leave responseGain at zero**, while
ambient interference continues to sample `--visual-time` normally. No new CLI
flag or replay-file field is required for this slice.

The response is reproducibly captured through the real offscreen renderer test
harness: explicitly submit target-at-time events, then render requested ages. Save
these images alongside a real interactive video. This limitation must be reported
in the implementation status: independent CLI stills show a settled LCD, not a
colour change whose timestamp they do not know. Full replay-event reconstruction
is a separate future feature, not a reason to compromise capture determinism.

If lifetime/reset integration proves ambiguous, land A green first and report B
as incomplete with the concrete blocker. Do not silently substitute a recurring
highlight pulse and call it colour-change response. Both requested effects are
required before calling the overall request complete.

## Tests first and actual artifact checks

### Checkpoint A — ambient, independently committable

1. Extend the existing LED transport tests in
   `tests/render/test_offscreen_render.cpp` around “LED patch coordinates stay
   attached through slide and inversion”. Assert equal seeds for one logical cell
   across flat/shape construction and poses; adjacent cells have variation;
   non-LED objects/sidewalls do not acquire active effect payloads. Assert signal
   layout/attribute offsets with the existing mesh ABI checks.
2. Reuse “LED cells resolve a pixel matrix nearby and filter to a steady mean afar”
   as an isolated slab/camera fixture. Existing seed-zero pixel tests stay steady.
   Enable one seeded slab and render a fixed 12-second set of samples, coarse first
   then a few finer samples around an observed difference. Assert some phases
   differ, repeated times are byte-identical after unrelated renders, and changes
   occupy a small interior rectangle. Use changed-pixel bounding boxes/counts and
   channel bounds, **not a test that reimplements the shader hash as an oracle**.
   Pin the discovered representative seed/time in the final regression fixture.
3. At close view, changed pixels should be below 5% of panel-face pixels and an
   individual channel difference should be at most 10/255, allowing quantization.
   Far-away fixture should be identical or within 1/255, not flicker. Corners,
   sidewalls, glass and zero-seed slab remain exact. Check a rotated sampled face
   and a real torus/Klein pose for panel attachment and rail preservation.
4. Record a 12-second stationary standard-board sequence at normal play framing.
   Review it at normal speed: events should be barely noticed until pointed out,
   not read as available moves or defective hardware. Inspect 1× and 3× UI views,
   bright/dark cells and a distant higher-dimensional board. Preserve saturation,
   colour-contrast, topology and Vulkan-validation gates.

Commit A after targeted LED/render tests, real artifacts and precommit are green.
Suggested title: `render: add sparse cell-local LED interference`.

### Checkpoint B — response, independently committable

1. Unit-test actual target change, no-change repeated observations, first exposure,
   same-time idempotence, full settle by 0.24s, latest change replacing older change,
   threshold, alpha-only input, missing/reappearing cells, explicit reset and time
   rewind. Compare timestamps/outputs across different extra no-change redraws.
2. Exercise real snapshot selection on e2: selected and legal destination colours
   trigger; an unrelated cell does not. Deselect, hover, actual e2–e4 last-move
   marks, hint/peek changes and relevant display-option resets cover the existing
   colour sources. Repeat on a shape board. Position/history/picking results must
   match a helper-disabled run exactly.
3. Render new target colour settled versus ages 0, .06, .12, .24. The new target is
   already present at age zero; difference fades and is zero at .24. Stable target
   and alpha do not flicker. Guard rail/sidewall and piece regions against changes.
   Keep ambient time fixed for this response-only comparison, or use its quiet
   fixture phase. Do not confuse hologram scan differences with LCD response.
4. Repeat M23.5 standard saved-game still/clip equality both themes and scales;
   default CLI gain remains zero. Ambient is explicit-time and agrees at equal
   global samples. Repeated --shot with extra warmups must remain identical.
5. Live artifact: stationary board for ambient, then hover/select/deselect and
   make/undo a move while recording. Review at normal speed and compare matched
   response-only offscreen images. Reject delayed/ambiguous legal colours, broad
   flashes or a visible repeated selection pulse. Record the capture limitation.

Run targeted render tests and relevant GUI material/visual-clock/HUD gates, then
`tools/precommit.sh`. Update `AGENTS.md`'s material/animation map and M23 status when
implemented; no gameplay command or replay semantics change. Suggested B commit:
`render: settle changed LED cell colours with explicit visual time`.

## Status

- A ambient implementation and tests complete. Mesh vertices are 68 bytes and instances
  96 bytes; the added payload is 12 bytes in each. Cell-local seeds survive flat/shape
  presentation, slide and inversion. Full rail weights and sidewalls suppress effects.
- All 183 render cases pass (6,032,379 assertions), as do all 43 GUI gates with
  Vulkan validation on, on llvmpipe (Mesa 26.2.3). The targeted LED cases prove
  repeatable phases, sparse interior bounds, far filtering and unchanged other materials.
- The isolated 512-pixel fixture at 6.75 seconds changes 672 pixels in a
  61-by-13-pixel interior rectangle, with maximum channel departure 3/255.
  Native and amplified difference images are in `out/m23/led-ambient/`.
- Actual board captures cover standard at 1×/3×, torus, posed Klein and hyper4.
  A 22.60-second stationary live sequence (120 RGB frames) checks ordinary
  flat-board framing: the maximum interior difference against its initial frame
  is 43 pixels, at most 2/255 per channel. Effects are barely perceptible at
  native size; amplified differences reveal isolated interior strips. A second
  12-second, 30fps lossless RGB recording reads the live Xvfb framebuffer directly
  (`live-stationary-30fps.mp4`), avoiding screenshot sampling gaps.
- Full precommit gate passed: staged C++ formatting, build, architecture, unit
  (61.47 seconds) and property suites. Astra read-only review found no blockers.
- B response helper/lifetime integration, tests and artifacts: pending.
- Default independent capture response remains settled by design; ambient animates.
