# M24.3 — The bench projector shows the menu's object as a real hologram

Status: **built 2026-11-12.** Third slice of M24. Requires M24.1 and M24.2.

Read first: `docs/plan/M24-the-rig.md` ("Rules for every M24 slice", "The machine"), and
the Status of M24.1 and M24.2.

Written for an implementer who has not seen the design conversation. Follow it
literally. If a name here does not exist in the code, stop and report it.

## Goal of this slice

Today each menu screen draws a decorative object flat with ImGui into the left half of
the screen:

| Screen | Object | Drawn by |
|---|---|---|
| MainMenu, Welcome | the Calabi–Yau quintic ("manifold") | `drawManifold` in `src/render/deco.cpp`, via `drawDeco(..., Deco::Manifold, ...)` |
| NewGame (Library) | the selected variant's overture (flat 8×8 forming its shape) | `Ui::drawOvertureObject` → `drawOverture` in `src/render/overture_scene.cpp` |
| Settings | a turning 4-cube | `drawDeco(..., Deco::Tesseract, ...)` |
| Editor | a move atom | `drawDeco(..., Deco::Atom, ...)` (**out of scope**: the editor keeps its flat backdrop) |

With the lab on, these become **3-D hologram instances** standing above the bench
projector, drawn by the board pipeline with the hologram material (matId 4). Its scan
lines, glow and bloom come for free. The flat ImGui versions are not drawn while the lab
is on. With the lab off, nothing changes.

The hologram:
- stands centred on the anchor `projector.lens`, its centre 0.32 m above the lens;
- fits a sphere of radius 0.20 m;
- turns slowly about the vertical axis (the same turn rate the flat object uses today);
- can still be dragged to turn it, because `updateObjectDrag` keeps working, now in 3-D
  around the vertical axis;
- has a faint **beam cone** from the lens up to the object's base, so it obviously comes
  from the projector.

## Background you need

- `render::OvertureScene` (`src/render/overture_scene.hpp`) holds `quads` (`OvQuad`, 4
  corners in `OvVec3`), `tokens` (`OvToken`: a piece at a point with a normal, a glyph
  and a colour), `trails`, `bursts` and a camera `cam` (`yaw`, `elev`, `reach`,
  `persp`). The overture's world is **Y up** (the comment on `OvVec3`): the flat board
  lies in y = 0, files run along x and ranks along z.
- `OvQuad::tone` is an `OvTone`: Light, Dark, Lit, Scorch, Mirror or Scrim. Colours are
  picked in `drawOverture` from the theme. Read that function (`overture_scene.cpp`,
  around line 3314) and copy its tone→colour mapping exactly, so the 3-D version has
  the same palette.
- `Ui::drawOvertureObject` (`src/render/ui.cpp`, around line 970) shows how the scene is
  built and cached (`overtureCache_`) and how the drag adds `objectYaw_` and
  `objectElev_`.
- `quinticPoint(k1, k2, x, y)` in `src/render/quintic.hpp` returns a 3-D point of the
  quintic surface. `drawManifold` (`deco.cpp`, around line 121) tiles it. Read it and
  use the same patches, tiling and colours.
- The tesseract decoration: find it in `deco.cpp` (grep `Tesseract`). It projects a 4-D
  cube to 3-D, then to 2-D. You need the 3-D stage: its edges as 3-D segments.

## Step 1 — a pure 3-D hologram model (test first)

Create `src/render/projector_hologram.{hpp,cpp}`:

```cpp
namespace cb::render {

/// One frame of the projector's hologram in the renderer's world, ready to draw.
struct Hologram {
  std::vector<Instance> quads;   ///< hologram-material thin boxes, one per face
  std::vector<Instance> tokens;  ///< pieces, by shape (see batches)
  std::array<InstanceSet::Batch, kShapeSlots> tokenBatches{};
  std::vector<Instance> lines;   ///< thin boxes for edges (tesseract, trails)
  Instance beam{};               ///< the cone from the lens; alpha in color[3]
  bool any() const noexcept { return !quads.empty() || !tokens.empty() || !lines.empty(); }
};

/// Where and how big: world position of the hologram's centre, its radius in world
/// units, and its turn about world Z (radians).
struct HologramPlacement {
  view::Vec3 centre{};
  float radius{1};
  float yaw{0};
  float alpha{1};   ///< 0..1, multiplies every colour's alpha (screen moves use it in M24.4a)
  float scale{1};   ///< extra uniform scale (screen moves use it in M24.4a)
};

[[nodiscard]] Hologram overtureHologram(const OvertureScene& scene, const view::Theme& theme,
                                        const HologramPlacement& at);
[[nodiscard]] Hologram manifoldHologram(float seconds, const view::Theme& theme,
                                        const HologramPlacement& at);
[[nodiscard]] Hologram tesseractHologram(float seconds, const view::Theme& theme,
                                         const HologramPlacement& at);
/// The beam from the lens (world) up to the hologram's base.
[[nodiscard]] Instance projectorBeam(view::Vec3 lens, const HologramPlacement& at,
                                     const view::Theme& theme);

}  // namespace cb::render
```

### Mapping overture coordinates to the world

For a point `q` in overture space:
1. **Centre and normalise:** `u = (q − c) / R`.
   - `c` is the centre of the scene's bounds: the midpoint of the min and max over all
     quad corners and token positions.
   - `R` is `max(scene.cam.reach, 1e-3)`. That `reach` grows as the shape zooms out, and
     using it keeps the overture's own zoom.
2. **Axes:** overture (x, y, z) with Y up maps to world (x, −z, y) with Z up.
   - Verify by capture: from the `library` station, the standard board's a1 corner must
     be nearest the viewer on the left, as in today's flat overture at its default yaw.
   - If it is mirrored, use (x, z, y) and note it.
3. **Turn:** rotate about Z by `at.yaw + scene.cam.yaw`.
   - `scene.cam.elev` is the flat overture's camera elevation. In 3-D the station camera
     provides the elevation, so ignore `elev`, except for the player's drag, which is
     applied in Step 4.
4. **Place:** `world = at.centre + u * at.radius * at.scale`.

### Quads

Each `OvQuad` becomes one `Instance` of the **Box** lab mesh (`LabShape::Box`, M24.1),
flattened to a thin tile:
- **centre:** the mean of the 4 mapped corners;
- **orientation:** build an orthonormal basis.
  - Edge `e1 = p1 − p0` and edge `e2 = p3 − p0`.
  - The normal is `n = normalize(cross(e1, e2))`.
  - The tangent is `t = normalize(e1)` and the bitangent `b = cross(n, t)`.
  - Convert the matrix [t b n] to a quaternion for `Instance::quat`. Write
    `quatFromBasis` in `projector_hologram.cpp`, and test it.
- **scale:** (|e1|, |e2|, 0.02 × radius_world / 1.0).
  - The quads are not exactly parallelograms. Using |e1| and |e2| leaves hairline gaps or
    overlaps; that is acceptable for a hologram.
  - If gaps are visible in captures, multiply x and y by 1.04.
- **colour:** the tone→colour mapping from `drawOverture`, with `fade` multiplying alpha.
  A `hasColour` quad uses `colour`.
- **material:** `shaderMaterial(view::Material::Hologram, Cut::Plank, 0)`;
- **fxCell:** 0.

### Tokens

Each `OvToken` becomes one piece instance:
- **shape:** the archetype for its glyph. Grep how the board renderer picks an
  archetype from a piece (`archetypeFor` or the variant's piece model). For the
  overture's standard glyphs (P N B R Q K), map them to Dome, Wedge, Spire, Tower,
  Crown and Monolith.
- **position:** the mapped `at`.
- **orientation:** the piece's local +Z turned onto the mapped `normal` (a quaternion
  from +Z to n).
- **scale:** `token.height * radius_world * 0.10`. Tune by eye: pieces should be about
  1.5 tiles tall.
- **colour:** white or black piece colour from the theme, the same tokens `drawOverture`
  uses. Alpha is `fade * at.alpha`.
- **material:** Hologram (matId 4).
- Add each to the batch for its archetype, as the board renderer does
  (`byShape[archetype]`).

### Trails and bursts

- **Trails:** each segment of `pts` becomes a thin Box from one point to the next, with a
  width of 0.006 × world radius. Use its colour and `fade`. Dashed trails: skip every
  other segment.
- **Bursts:** skip them in this slice; note it in Status. They are momentary flashes in
  some overtures.

### The manifold

`manifoldHologram(seconds, theme, at)`:
1. Generate the same patch tiling `drawManifold` uses. For each tile, compute its 4
   corners with `quinticPoint` in its own 3-D space.
2. Map them with the same centre/normalise/turn/place steps. Here `c` and `R` are the
   bounds' centre and the bounds' radius (the quintic's natural extent; compute them
   once).
3. The turn is `at.yaw + seconds × ω`, where ω is the manifold's current turn rate in
   `drawManifold`. Copy the constant.
4. Colours and alpha: the same semi-transparent black and white `drawManifold` uses
   (read the alpha constant).
5. Keep the vertex count sane. If `drawManifold` draws thousands of tiles, that is
   fine: they are instances, and the instance buffer grows (`ensureInstanceCapacity`).
   Note the count in Status.

### The tesseract

`tesseractHologram`: take the 4-D → 3-D stage from the tesseract decoration. Each of the
32 edges becomes a thin Box line, with width 0.01 × world radius, the hologram material
and the theme's accent colour. Use the same rotation speeds as the flat version.

### The beam

`projectorBeam(lens, at, theme)`:
- a **Cylinder** (lab mesh) from the lens up to the hologram's lowest point, which is
  `at.centre.z − at.radius`;
- diameter 0.08 m at the bottom. A cylinder cannot taper, so use a constant width of
  0.10 m; note it;
- the hologram material, the colour the theme's hologram cyan (grep the theme for the
  hologram/LED accent), alpha 0.12 × `at.alpha`;
- **drawn blended**, not opaque (see Step 3).

**Tests** (`tests/render/test_projector_hologram.cpp`, `[unit][render][hologram]`):
1. `overtureHologram(overtureScene(Overture::Standard, 0.0f, false, theme), ...)`:
   - the quad instance count equals the scene's quad count;
   - the token count equals the scene's token count;
   - every centre lies within `at.radius × 1.05` of `at.centre`.
2. The same at `t = 1` for `Overture::T6` and `Overture::Torus3d`: all centres stay
   within the radius.
3. `quatFromBasis` of the identity basis is the identity, and it maps +X to `t` and +Z to
   `n` for a random orthonormal basis (fixed seed).
4. With `at.alpha = 0`, every instance's alpha is 0.
5. `manifoldHologram`: non-empty, and every instance is inside the radius.
6. `tesseractHologram`: exactly 32 line instances.

## Step 2 — choose what to show, and drive it from the Ui

The UI owns the decision of which object a screen shows, and the caching. Keep it
there.

1. In `Ui`, add
   `[[nodiscard]] HologramRequest hologramRequest() const;`, returning
   `{ enum Kind { None, Manifold, Overture, Tesseract } kind; float seconds; float yaw;
   float alpha; float scale; }`. Fill it during `build()`, in the same place the flat
   decoration is decided (the code around `decoForScreen` and `drawOvertureObject`,
   around line 1055):
   - `kind` from `decoForScreen`: Manifold → Manifold, Tesseract → Tesseract; NewGame
     shows Overture; everything else (including Atom/Editor) → None;
   - `seconds = clock_`;
   - `yaw = objectYaw_`;
   - `alpha` and `scale` are 1 in this slice. M24.4a animates them during screen moves;
   - for Overture, also expose the cached scene:
     `const OvertureScene* overtureScene() const`, returning `&overtureCache_` after the
     cache refresh. **Move the cache refresh out of `drawOvertureObject` into a function
     both paths call**, so it is refreshed even when the flat object is not drawn.
2. When the lab is on (`labBackdrop_` from M24.1), **skip** the flat `drawDeco`,
   `drawOvertureObject` and the leaving-ghost `drawDeco` calls, but still compute the
   request and keep the cache fresh.
3. `updateObjectDrag` keeps working on the same screen rectangle (the left half). Its
   `objectYaw_` feeds `yaw`. `objectElev_` is ignored in the lab, because the station
   camera sets the elevation. Note it.

## Step 3 — draw it

1. Add to `InstanceSet`:
   ```cpp
   /// The projector's hologram (M24.3): opaque-pass tiles/lines/tokens with the hologram
   /// material, and the beam, which is blended.
   std::vector<Instance> holo;                         // quads + lines, Box mesh
   std::vector<Instance> holoTokens;
   std::array<Batch, kShapeSlots> holoTokenBatches{};
   std::vector<Instance> holoBeam;                     // 0 or 1, Cylinder mesh, blended
   ```
2. In `BoardRenderer::record`, draw `holo` and `holoTokens` with the pipeline the board's
   hologram pieces use.
   - Hologram pieces today are drawn in the opaque per-shape pass: matId 4 discards
     fragments for its scan and dropouts (`board.frag` around line 269). Use the same
     pipeline and an instance base like `labBase`.
   - Draw `holoBeam` with `blendPipeline`, **after** the opaque passes, like the shadows.
   - Check that the hologram material honours `color.a` as opacity. If it only uses
     `CellFx::opacity` (`fx.c.x`), you need a per-instance alpha path. The fx record is
     shared per cell, so instead give hologram instances with `fxCell == 0` an opacity
     from `fragColor.a`. Read the matId 4 branch and add, minimally: for `fxIndex == 0`,
     `opacity = fragColor.a`. Then verify that **no existing hologram instance** has
     `fxCell == 0` with alpha < 1. Grep where pieces are emitted (`emitPiece`) and
     confirm that pieces always carry an fx index. If they don't, gate on a new flag
     instead and note it.
3. In `main.cpp`, on the lab path (M24.1 Step 5), after `lab.appendTo(...)`:
   ```cpp
   const auto req = (*ui)->hologramRequest();
   render::HologramPlacement at;
   at.centre = lab.toWorld(lensPlus(0.32));   // anchor projector.lens + 0.32 m in z
   at.radius = 0.20f * render::kCellsPerMetre;
   at.yaw = req.yaw; at.alpha = req.alpha; at.scale = req.scale;
   render::Hologram h;
   switch (req.kind) { /* call the matching builder */ }
   // append h into instances.holo / holoTokens / holoTokenBatches / holoBeam
   ```
   The beam is added only when `h.any()`.
4. **The projector light** (M24.2 `projector`, group `machine`): scale its intensity by
   `0.5 + 0.5 × (h.any() ? 1 : 0)`, so the bench brightens when something is projected.
   Add an `intensityScale` parameter for one named light to `labLightBlock`, or patch the
   block after building it.

## Step 4 — the drag in 3-D

`objectYaw_` already turns the hologram through `at.yaw`. Nothing more is needed. Check
that dragging on the left half of the screen still turns it, and that the turn
direction feels right (drag right = the front moves right). If it is reversed, negate
it in the lab path only.
