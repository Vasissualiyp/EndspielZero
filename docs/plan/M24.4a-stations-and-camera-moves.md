# M24.4a — Menu screens are camera stations; moving between them flies the camera

Status: **planned 2026-11-12.** Requires M24.1–M24.3. The implant layer is M24.4b, a
separate slice.

Read first: `docs/plan/M24-the-rig.md` ("Rules for every M24 slice", "Camera stations",
"The moves"), and the Status of M24.1–M24.3.

Written for an implementer who has not seen the design conversation. Follow it
literally. If a name here does not exist, stop and report it.

## Goal of this slice

With the lab on, changing between two **menu** screens (any two screens that do not show a
board, excluding the Editor) is a camera move between their stations, with mass. The
projector's hologram collapses into the lens and the next one grows out. The object a
screen is about gets a soft **salience** glow in the room. At calm intensity the move is a
0.3 s cross-fade.

Not in this slice:
- menu ↔ game moves (M24.5, the slab deploy);
- the implant composite, i.e. panels forming, dissolving, heartbeat and the saccadic
  dip (M24.4b). Panels in this slice keep the existing M23.11 behaviour, except the
  timing rule in Step 4.

## Background you need

- **The shell's one transition clock** is `Ui::enter_` (`src/render/ui.hpp`, around
  line 418).
  - It runs 0 → 1 per screen change. A change is classified by
    `app::classifyMove(from, to)` (`src/app/screen_transition.hpp`) into
    `ScreenMove::{Cut, MenuToGame, GameToPause, PauseToGame, GameToMenu}`.
  - `moveSeconds(move, intensity)` gives the duration. A move's age in seconds is
    `enter_ * moveSeconds`.
  - `Cut` moves (menu ↔ menu today) use the old pane move (`Ui::paneMove()`, around line
    1438; `outEase`, `inEase`, `kInStart`, `kOutEnd`).
- `Ui::skipTransition()` sets `enter_ = 1`; any key or mouse-down calls it.
- `Ui::pinTransitionAge(seconds)` pins the age for captures (`--from <screen>
  --transition-t <s>`).
- `render::LabScene::station(name)` (M24.1) returns an `OrbitCamera`. The screen → station
  map is `stationFor` in `main.cpp` (M24.1 Step 5).
- `Ui::hologramRequest()` (M24.3) carries `alpha` and `scale`. Both are 1 in M24.3; this
  slice animates them.

## Step 1 — pure camera blending (test first)

New files `src/view/rig_move.{hpp,cpp}`. Add them to `src/view/CMakeLists.txt` beside
`camera.cpp`.

```cpp
namespace cb::view {

/// The camera between two stations at eased progress `s` (0..1, may overshoot a little,
/// see rigEase). Target: straight line. Distance: geometric (log) interpolation, plus a
/// lift of `kRigLift` x the mean distance at the middle (sin(pi*s)), so the camera steps
/// back a little while it turns. Yaw: the shorter way round. Pitch and fovY: linear.
/// nearZ/farZ/orthographic/roll come from `to`.
[[nodiscard]] OrbitCamera blendCamera(const OrbitCamera& from, const OrbitCamera& to, float s);

/// Ease with mass: a cubic ease-in-out with a small settle past the end.
///   c(x) = x < 0.5 ? 4x^3 : 1 - (-2x+2)^3 / 2
///   settle(x) = kRigSettle * sin(pi * clamp((x - 0.72) / 0.28, 0, 1))
///   rigEase(x) = c(x) + settle(x) * (1 - c(x)) ... see below
/// Exactly 0 at x <= 0 and exactly 1 at x >= 1.
[[nodiscard]] float rigEase(float x) noexcept;

/// How long a move between two stations takes, seconds, from how far the camera turns
/// and travels. Clamped to [kRigMinSeconds, kRigMaxSeconds].
[[nodiscard]] float rigMoveSeconds(const OrbitCamera& from, const OrbitCamera& to,
                                   float metresPerUnit) noexcept;

/// The camera's angular speed (rad/s) at `age` of a move of `seconds`, by a central
/// difference of the view direction over +-5 ms. 0 outside the move. M24.4b's saccadic
/// dip reads it.
[[nodiscard]] float rigAngularSpeed(const OrbitCamera& from, const OrbitCamera& to,
                                    float age, float seconds) noexcept;

inline constexpr float kRigLift = 0.08f;
inline constexpr float kRigSettle = 0.018f;
inline constexpr float kRigMinSeconds = 0.6f;
inline constexpr float kRigMaxSeconds = 1.1f;

}  // namespace cb::view
```

Exact formulas:
- **The settle.** We want a slight overshoot that comes back to exactly 1 at x = 1. Use
  `rigEase(x) = c(x) + kRigSettle * sin(π · clamp((x − 0.72) / 0.28, 0, 1))`.
  - At x = 1 the sine term is `sin(π) = 0` in exact arithmetic, but `std::sin(π)` in
    float is about −8.7e-8, not 0. So **return exactly 1.0f for x ≥ 1** and exactly 0 for
    x ≤ 0.
  - Because c(0.72..1) is already near 1, the sum exceeds 1 by up to about 0.018 around
    x ≈ 0.86, then returns. That is the settle.
- **Yaw the shorter way:** `d = remainder(to.yaw − from.yaw, 2π)` (`std::remainder`), and
  `yaw = from.yaw + d · s`.
- **Distance:** `exp(mix(log(from.distance), log(to.distance), s))`, then
  `+ kRigLift · 0.5 · (from.distance + to.distance) · sin(π · clamp(s, 0, 1))`.
- **`rigMoveSeconds`:**
  ```
  ang = |remainder(Δyaw, 2π)| + |Δpitch|            // radians
  far = |Δtarget| * metresPerUnit                   // metres
  seconds = clamp(0.55 + 0.25*ang + 0.08*far, kRigMinSeconds, kRigMaxSeconds)
  ```
- **`rigAngularSpeed`:**
  - `v(t)` = the unit view direction `normalize(target − eye())` of
    `blendCamera(from, to, rigEase(t / seconds))`;
  - the result is `acos(clamp(dot(v(age − 0.005), v(age + 0.005)), −1, 1)) / 0.01`;
  - clamp the sample times to [0, seconds].

**Tests** (`tests/unit/view/test_rig_move.cpp`, `[unit][view][rig]`):
1. `blendCamera(a, b, 0) == a` and `blendCamera(a, b, 1) == b`, field by field, within
   1e-5. Yaw is compared modulo 2π.
2. Yaw goes the short way: a = 350°, b = 10° gives 0° (mod 2π) at s = 0.5.
3. `rigEase(0) == 0` and `rigEase(1) == 1` exactly. The maximum over (0, 1) is in
   (1.0, 1.02]. The function is monotonic on [0, 0.7].
4. `rigMoveSeconds` is symmetric, clamped, and gives 0.6 for identical stations.
5. `rigAngularSpeed` is 0 for identical stations and > 0 in the middle of a 90° turn.

## Step 2 — a `Station` move on the shell clock

1. In `src/app/screen_transition.hpp`, add a `ScreenMove::Station` value with this
   comment: "both screens are lab menu screens: the camera flies between their stations
   (M24.4a)".
   - `classifyMove` cannot know about the lab (the app layer has no renderer). So do
     **not** change `classifyMove`. Instead, the `Ui` upgrades a `Cut` to `Station` when
     the lab is on, **and** both the leaving and the arriving screen are lab menu
     screens. A lab menu screen is one with `!showsBoard`, excluding Editor; the Ui
     already knows this through `labBackdrop_`. Record whether the leaving screen was on
     the lab path, as `labLeaving_`, at the moment the screen changes (around line
     1612, where `leaving_` is set).
2. `moveSeconds(Station, intensity)`: at calm, `kCalmFadeSeconds`. Otherwise the duration
   is not a constant: it comes from `rigMoveSeconds` for the two stations. Since
   `moveSeconds` is pure in `app` and has no station data, give `Ui` a member
   `float stationSeconds_` set at the change from
   `view::rigMoveSeconds(fromCam, toCam, 1 / kCellsPerMetre)`, and use it wherever the
   Ui computes the age for a Station move. Grep `moveSeconds(` in `ui.cpp`; there are a
   few call sites. Wrap them in a private `float Ui::currentMoveSeconds() const` that
   returns `stationSeconds_` for Station moves and `moveSeconds(move_, intensity_)`
   otherwise.
3. `moveFx(Station, age, intensity)`: return a `MoveFx` with:
   - full intensity: `leaveAlpha = 1 − smooth(age / (0.35 · T))`;
     `arriveAlpha = smooth((age − 0.55 · T) / (0.45 · T))`; traces 1; `done` once
     age ≥ T. `T` is the move's seconds. Pass it in by adding an overload
     `moveFx(ScreenMove, float age, float intensity, float seconds)`, and keep the old
     signature calling it with `moveSeconds(...)`;
   - calm: the existing calm cross-fade.
4. The Ui needs the two cameras at the change. Give `Ui` a callback set by `main.cpp`:
   `std::function<std::optional<view::OrbitCamera>(app::Screen)> stationCamera_`, which
   returns `lab.station(stationFor(screen))` when the lab is on and nullopt otherwise.
   Store `fromCam_` and `toCam_` at the change.
   - **Mid-move changes:** if a change happens while a Station move is still running (the
     player clicks again before arrival), the new `fromCam_` must be the **current
     blended camera**, not the old station. Otherwise the camera jumps. Compute it with
     `blendCamera(fromCam_, toCam_, rigEase(age / T))` before overwriting.

## Step 3 — the camera follows the move

1. Add `[[nodiscard]] std::optional<view::OrbitCamera> Ui::labCamera() const;`.
   - During a Station move: `blendCamera(fromCam_, toCam_, rigEase(age / T))`.
   - Otherwise: `toCam_` if set.
   - At calm: `toCam_` (the camera cuts; the panels cross-fade).
2. In `main.cpp` on the lab path, use `(*ui)->labCamera()` when it has a value, falling
   back to `lab.station(stationFor(screen))`. `--station` still overrides both.
3. `skipTransition()` already ends the move (enter_ = 1), and the camera snaps to the
   arrival. Check this with a test (Step 6).

## Step 4 — panels and the hologram during a Station move

1. **Panels.** `Ui::paneMove()` for a Station move:
   - `ghosting_` (the leaving pane): `{1.0f, fx.leaveAlpha, 1.0f}`;
   - arriving: `{1.0f, fx.arriveAlpha, 1.0f}`.

   No scale and no trace: the camera is the motion now. **The arriving pane must not take
   input before `arriveAlpha > 0.5`.** Find how the pane builders disable interaction
   for ghosts (the `!ghosting_` arguments in `ui_menus.cpp`) and pass
   `!ghosting_ && arriveAlpha > 0.5f` for Station moves. Grep each `beginScreenPane(`
   call; there are about ten.
2. **The hologram.** In `Ui::hologramRequest()`, for a Station move:
   - if the leaving and arriving screens request the **same** kind and subject (for
     example NewGame ↔ NewGame never happens, but Welcome ↔ MainMenu are both Manifold),
     keep it at alpha 1 and scale 1 throughout;
   - otherwise there are two phases:
     - **0 ≤ age < 0.4 T (collapse):** show the *leaving* kind, with
       `scale = 1 − smooth(age / (0.4 T))` and `alpha = 1 − smooth(age / (0.4 T))`. Add
       a **vertical squash**: the hologram should fall into the lens, not shrink to its
       centre. Add a `squashZ` field to `HologramRequest` and `HologramPlacement`, equal
       to `scale²`, applied only to world Z about the lens point. The builders apply it
       as `world.z = lens.z + (world.z − lens.z) · squashZ`;
     - **0.5 T ≤ age < T (grow):** show the *arriving* kind, with
       `scale = smooth((age − 0.5 T) / (0.5 T))`, `squashZ = scale` and the same alpha.
     - Between 0.4 T and 0.5 T: nothing (`kind = None`), so the beam is off as well.
   - The leaving kind needs the leaving screen's subject. For the overture, that is the
     cached scene of the leaving variant. Keep the last scene in a second cache slot,
     `overtureLeaving_`, copied at the change.
3. **The projector light** follows the hologram: M24.3 Step 3.4 already scales it by
   `h.any()`. Make that `0.5 + 0.5 · alpha` so it fades with the collapse.

## Step 5 — salience: the object the screen is about glows

1. **Lab file:** add an optional key to `[[part]]`: `focus = "projector"` (free text, used
   to group parts). Parse it in `lab_doc` (default empty).
   - Give the projector parts `focus = "projector"`;
   - the magazine frame and its dummy slabs `focus = "magazine"`;
   - the door panel and slats `focus = "door"`;
   - the bench top `focus = "bench"`.
2. **Screen → focus:**
   - MainMenu, Welcome and Watch → `projector`;
   - NewGame → `magazine`;
   - Settings, GameInfo and PieceMoves → `bench`;
   - QuitConfirm → `door`;
   - else → none.

   Put the map in `main.cpp` beside `stationFor` as `focusFor`.
3. **Easing:** salience is pure in the move age.
   - The arriving focus goes `smooth(age / 0.3)` from 0 to 1, starting at
     `age = 0.5 T`.
   - The leaving focus goes `1 − smooth(age / 0.3)`, starting at `age = 0`.
   - With no move running, the current focus is at 1.

   Implement it as `Ui::salience(std::string_view focus) const → float`, which `main.cpp`
   passes into `LabScene::appendTo`. Add a parameter to `appendTo`:
   `const std::function<float(std::string_view)>& salience`.
4. **Into the instance.** For a lab part with salience `s > 0`, write `s` into
   `Instance::panelSignal[2]`.
   - **Check first** that `panelSignal[2]` is unused for non-LED materials (M24.1 used
     `panelSignal[1]` for AO).
   - Grep `panelSignal` in `board.frag`. Confirm that the non-LED branches never read it,
     and that every existing non-LED instance leaves it 0.
   - If it is not free, use the instance's `edge[3]` and set `edgeMask = 0`. Note your
     choice.
5. **The shader.** In `board.frag`, for `matId` 0, 1, 2, 3 and 6 with `sal > 0.0`:
   ```glsl
   float rim = pow(1.0 - abs(dot(n, normalize(push.eyePos.xyz - fragWorld))), 3.0);
   rgb = mix(rgb, rgb * 1.25, 0.5 * sal);                // a small local contrast lift
   rgb += lightBuf.implant.rgb * (0.10 + 0.55 * rim) * sal;  // the soft implant-hue rim
   ```
   `lightBuf.implant` is a new `vec4` at the **end** of the M24.2 light block.
   - Add `float implant[4]` to the end of `GpuLightBlock` and update its
     `static_assert`s.
   - Fill it from the theme's `implant` colour (added in M24.4b Step 1). If M24.4b is
     not built yet, add the theme token now with the value given there.
   - The neutral block's `implant` is zero, so the lab-off path is unaffected.
6. **Test:** a GPU render of the lab from `menu` with the projector's salience at 1 vs 0.
   The images differ in the projector's screen rectangle and are equal far away from it
   (bloom margin as in M24.3).

2. Ui-level tests (no GPU needed if `Ui` can be built headless; if not, put them in the
   GPU suite):

     --presentation 0`.

4. Run every existing gui ctest. `gui-screen-transition` runs without `--lab`, so it is
   unaffected.
