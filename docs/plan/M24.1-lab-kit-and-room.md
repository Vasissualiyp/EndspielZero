## Goal of this slice

Behind a new setting `labScene` (default **off** in this slice), the menu screens show a
static 3-D room instead of today's flat backdrop (the ink fill, the drifting polygon
field and the grid floor). The room is built from a data file of simple parts (boxes,
bevelled boxes, cylinders) drawn by the existing board pipeline. There are no lights yet
beyond what the board shader already does (§2), no projector hologram (§3) and no camera
moves (§4). The game screen is **not** changed in this slice.

When this slice is done:
- `--lab 1 --screen menu --shot x.ppm` shows the room from the main-menu station, with
  today's menu panel drawn over it;
- `--lab 0` (and every existing capture, which defaults to it) is byte-identical to
  before.

## Coordinate conventions (read carefully)

- The board renderer's world is **Z up**, X right and Y away from a camera with yaw 0.
  `view::OrbitCamera::eye()` in `src/view/camera.cpp` is
  `target + (sin(yaw)·cos(pitch), −cos(yaw)·cos(pitch), sin(pitch)) · distance`. One
  world unit is **one cell pitch**.
- The lab file is written in **metres**, with the same axes: Z up, X right, Y away. That
  way a human can edit it with a tape measure in mind.
- The conversion is `world = (metres − deployCentre) × kCellsPerMetre`:
  - `kCellsPerMetre = 20.0f`, so one cell is 5 cm and a standard board is 40 cm across;
  - `deployCentre` is the anchor `gantry.centre` in the lab file.

  So the lab's world origin is the centre of the deployment volume. That is where a board
  will hang in §5. In this slice no board is drawn in the lab.
- Angles in the file are **degrees**. Rotations are applied as Z, then Y, then X
  (yaw, pitch, roll) about the part's own centre.

## Step 1 — the file format and its parser (test first)

### The file: `assets/lab/lab.toml`

Use TOML, parsed with toml++, which `src/io` already uses for variants
(`src/io/CMakeLists.txt`: `find_package(tomlplusplus REQUIRED)`). Look at
`src/io/variant_toml.cpp` and copy how it opens a file, reports errors with line numbers
(`toml::parse_error`, `source().begin.line`) and returns `Result<T>`.

Schema:

```toml
version = 1

[anchors]                      # named points, metres
"gantry.centre"   = [0.0, 0.6, 1.05]
"projector.lens"  = [-0.6, 2.62, 1.00]
"magazine.front"  = [2.35, 1.8, 1.30]
"door.centre"     = [0.0, -2.98, 1.20]
"bench.top"       = [-0.3, 2.65, 0.92]

[[part]]
name     = "floor"             # unique, [a-z0-9._-]
mesh     = "box"               # box | bevel | cylinder | slab | "file:models/<name>.obj"
pos      = [0.0, 0.0, -0.05]   # centre, metres
size     = [5.0, 6.0, 0.10]    # full extents, metres (cylinder: [diameter, diameter, height])
rot      = [0.0, 0.0, 0.0]     # degrees: yaw (about Z), pitch (about Y), roll (about X)
material = "matte"             # matte | metal | glass | glow | hologram | led
color    = "#1A1C20"           # sRGB hex, or [r, g, b] linear 0..1
ao       = 0.0                 # 0..1 darkening baked toward the part's bottom (see Step 3)
group    = "room"              # free text: room | bench | rig | clutter; used by §2 and §4

[[station]]
name     = "menu"              # menu | library | watch | tutorial | settings | quit | ...
target   = [-0.15, 2.55, 1.20] # what the camera looks at, metres
distance = 1.55                # metres
yaw      = 12.0                # degrees, same meaning as OrbitCamera::yaw
pitch    = 14.0                # degrees
fov      = 50.0                # vertical field of view, degrees
```

Rules the parser enforces, each with a line number in the error:
- `version` must be 1.
- Every `part` needs `name`, `mesh`, `pos` and `size`. `rot` defaults to 0, `material` to
  `matte`, `color` to `#808080`, `ao` to 0 and `group` to `"room"`.
- Names are unique across parts, and across stations separately.
- `mesh` must be one of the listed values, or `"file:<path>"`, where the path is relative
  to the lab file's directory and points to a Wavefront OBJ file (see Step 2b).
  - A missing or unparsable file is an error naming the part, the path and the OBJ line.
  - An optional `fallback = "box" | "bevel" | "cylinder"` is used, with a warning
    printed once, if the file is missing. That keeps the room drawable while a model is
    being made.
- Every `size` component must be > 0, and every number finite.
- `color` is a 7-character `#RRGGBB` string (convert sRGB to linear with the same
  function the theme uses; grep `Rgba::hex` in `src/view/theme.hpp`) or an array of 3
  floats.
- Stations need every field. `fov` lies in (10, 120), `distance` > 0, and `pitch` in
  (−89, 89).
- Unknown keys are an error (`unknown key 'colour' in part 'bench'`), so typos are caught.

## Step 2 — the meshes

Lab parts are drawn by the board pipeline as instances. The pipeline draws instances of
meshes from `render::MeshLibrary` (`src/render/piece_mesh.{hpp,cpp}`). Each mesh is a
`MeshRange` into one shared vertex and index buffer. Indices are `uint16_t`, relative to
`MeshRange::vertexOffset`, so each mesh must stay under 65,536 vertices. The whole buffer
can be larger.

1. In `piece_mesh.hpp`, add:
   ```cpp
   /// Meshes for the lab (M24.1), in the same buffers as the pieces. Unit-sized: a box
   /// and a bevelled box span -0.5..0.5 on every axis, a cylinder has radius 0.5 and
   /// height 1 along Z, centred. The instance's `scale` sizes them.
   enum class LabShape : std::uint8_t { Box, Bevel, Cylinder, Count };
   ```
   Then add to `MeshLibrary`: `MeshRange labRanges[static_cast<std::size_t>(LabShape::Count)];`.
2. In `MeshLibrary::build`, after the existing appends, append the three meshes and fill
   `labRanges`, following the existing `range.firstIndex` / `vertexOffset` pattern
   around line 926:
   - **Box:** 24 vertices (4 per face, so each face has its own normal), 36 indices.
   - **Bevel:** a box whose 12 edges are chamfered by 0.04 of the unit size, flat-shaded
     (each face has its own vertices). Faces: 6 main, 12 edge chamfers, 8 corner
     triangles.
   - **Cylinder:** 32 segments. A side band with smooth normals (2 × 33 vertices), plus a
     top cap and a bottom cap (centre + 33 rim vertices each) with flat normals.

   Fill every `MeshVertex` field:
   - `color` white;
   - `panelCoord` and `panelSignal` zero;
   - `panelPrev` `{0, 0, 0, -1}`;
   - `height`: read what the existing meshes put there (grep `height` in
     `piece_mesh.cpp`). If it is the vertex's normalised height for pieces, set it to
     `z + 0.5` so the `ao` term in Step 3 can use it.

   Read `MeshVertex` (line ~10 to ~38) and fill **every** field. An uninitialised field
   here is a validation or visual bug.
3. "Slab" in the file means the existing board cell mesh, `Archetype::Cell`. It is used for
   the magazine's dummy slabs. Map `LabMesh::Slab` to `meshes_.ranges[Archetype::Cell]`.
4. **Test** in `tests/render/test_piece_mesh.cpp` (or create it and register it):
   - each lab range has `indexCount > 0`, a multiple of 3, and an `indexCount` that
     stays inside the buffer;
   - every vertex of the Box lies within ±0.5 + 1e-6;
   - every normal has unit length;
   - the Cylinder's side vertices have radius 0.5 ± 1e-5.

## Step 2b — mesh files (OBJ)

Some lab parts are real models, made by a separate modelling agent; see
`docs/plan/M24-lab-models.md` for the list and the conventions. Load them as follows.

1. **Parser:** `src/io/obj_mesh.{hpp,cpp}`, pure, with no graphics dependency:
   ```cpp
   struct ObjMesh {
     std::vector<std::array<float,3>> positions;  // per output vertex
     std::vector<std::array<float,3>> normals;    // per output vertex, unit length
     std::vector<std::uint32_t> indices;          // triangles
   };
   [[nodiscard]] Result<ObjMesh> parseObj(std::string_view text, std::string_view name);
   ```
   - Support `v x y z`, `vn x y z` and `f` with `a`, `a//n` or `a/t/n` forms (texture
     indices are ignored), plus negative (relative) indices. Faces with more than 3
     vertices are fan-triangulated.
   - Ignore `o`, `g`, `s`, `usemtl`, `mtllib`, `vt` and comments.
   - Any other keyword is an error with its line number.
   - **No normals in the file** (or a face without them): compute flat face normals and
     give the face its own vertices.
   - **De-duplicate** identical (position, normal) pairs.
   - **Limits:** at most 65,535 output vertices per file (the index buffer is 16-bit per
     mesh range); more is an error that says to decimate the model.
   - **Conventions** (see `M24-lab-models.md`): metres, Z up, and the part's origin is the
     model's origin. The lab file's `pos` places that origin, and `size` is a
     **multiplier** for file meshes. `size = [1, 1, 1]` means "as modelled". State this
     in the parser's header comment, and note it in `lab.toml` next to the first file
     part.
2. **Tests** (`tests/unit/io/test_obj_mesh.cpp`):
   - a quad with normals gives 2 triangles and 4 vertices;
   - a quad without normals gets flat normals;
   - negative indices work;
   - an unknown keyword is an error with its line number;
   - 70,000 vertices is an error.
3. **Into the renderer.** `MeshLibrary` is built once. Lab file meshes are known only after
   the lab loads, so add `std::vector<MeshRange> fileRanges` to `MeshLibrary` and a
   `BoardRenderer::addLabMeshes(const std::vector<io::ObjMesh>&) -> std::vector<std::uint32_t>`
   (the returned value is the index into `fileRanges` per mesh).
   - It appends to the vertex and index data and re-uploads geometry
     (`uploadGeometry`). Call it once after the lab loads, **before** the first frame,
     so no in-flight frame uses the old buffers.
   - If re-upload mid-life is unavoidable, wait for the device to be idle first
     (`vkDeviceWaitIdle`), and only at load.
   - Convert each OBJ vertex to a `MeshVertex` the same way the procedural lab meshes do
     (Step 2), with `height = (z − minZ) / (maxZ − minZ)`.
4. `LabScene` keeps, per file part, its `fileRanges` index. `appendTo` puts file parts in
   their own batches (`labFileBatches`: one batch per file mesh), drawn like the other
   lab batches. Their `scale` is `size × kCellsPerMetre`, because the files are in metres.

## Step 3 — `render::LabScene`

New files `src/render/lab_scene.{hpp,cpp}`, added to `src/render/CMakeLists.txt` next to
`board_fx.cpp`.

```cpp
namespace cb::render {

inline constexpr float kCellsPerMetre = 20.0f;

/// The lab as instances for the board pipeline (M24.1). Built once from the document and
/// rebuilt only when the document, the theme or the room light changes.
class LabScene {
 public:
  static Result<LabScene> create(io::LabDoc doc);
  /// Metres to the renderer's world (cells, origin at gantry.centre).
  [[nodiscard]] view::Vec3 toWorld(std::array<float, 3> metres) const noexcept;
  /// A station as the renderer's camera. `nullopt` if the name is unknown.
  [[nodiscard]] std::optional<view::OrbitCamera> station(std::string_view name) const;
  /// Append the lab's instances to `set` (see "Drawing" below).
  void appendTo(InstanceSet& set, const view::Theme& theme) const;
  [[nodiscard]] const io::LabDoc& doc() const noexcept { return doc_; }
 private:
  io::LabDoc doc_;
  view::Vec3 deployCentre_{};
};

}  // namespace cb::render
```

**`station()`** returns an `OrbitCamera` with:
- `target = toWorld(st.target)`;
- `distance = st.distance * kCellsPerMetre`;
- `yaw` and `pitch` converted to radians, and `fovY = radians(st.fov)`;
- `nearZ = 0.05f * kCellsPerMetre` (5 cm) and `farZ = 30.0f * kCellsPerMetre`.

**`appendTo()`** creates one `Instance` per part:
- `center = toWorld(pos)`.
- `scale` is in the mesh's local units. Look at how existing code turns a desired size
  into `scale`: the plinth divides by `cellHalf` (`plinthInstance`, around line 140 of
  `board_renderer.cpp`), because the Cell mesh is not unit-sized.
  - The new Box, Bevel and Cylinder meshes **are** unit-sized, so
    `scale = size * kCellsPerMetre`.
  - For `Slab`, divide by the Cell mesh's half extents as the plinth does.
- `quat`: from yaw (Z), pitch (Y) and roll (X) in radians, composed as Z·Y·X. There is
  no helper today. Write a small `quatFromYawPitchRoll` in `lab_scene.cpp` and test it
  (Step 6).
- `color = part.color` (alpha 1), multiplied by `(1 - 0.5 * ao)` at the bottom. Since
  instances carry one colour, do the AO cheaply: leave `color` as is, and put `ao` in
  `Instance::panelSignal[1]`, unused for non-LED materials. Then in `board.frag`, for
  `matId` 0/1/3 only, multiply `rgb` by `mix(1.0 - ao, 1.0, smoothstep(0.0, 0.6,
  fragHeight))`. **Check first** that `panelSignal[1]` reaches the fragment shader for
  non-LED materials and is zero for every existing non-LED instance. Grep
  `panelSignal` in `board.vert`, `board.frag` and `board_renderer.cpp`. If it is not
  free, skip AO in this slice and note it in Status.
- `material = shaderMaterial(...)` (grep `shaderMaterial(` in `board_renderer.cpp`;
  it takes a `view::Material`, a `Cut` and a variant number). Map
  `Matte→Matte, Metal→Metal, Glass→Glass, Glow→Glow, Hologram→Hologram, Led→Led`. Use
  `Cut::Plank` and variant 0. **LED parts must not get a cell fx record**: `fxCell = 0`.
- `fxCell = 0` for every lab instance, which means neutral effects.
- `edge`, `edgeMask` and `roll` stay zero.

**Drawing.** Add to `InstanceSet` (`board_renderer.hpp`, around line 165):
```cpp
/// The lab (M24.1): opaque parts, by lab shape. Drawn with the opaque pipeline after the
/// board's own batches. Empty unless the lab is on.
std::vector<Instance> lab;
std::array<Batch, static_cast<std::size_t>(LabShape::Count) + 1> labBatches{};  // +1: Slab
```
`appendTo` sorts parts by shape and fills `lab` and `labBatches`. In
`BoardRenderer::record`:
1. Copy how `scaffold` is handled. Search for `scaffoldBase` in `board_renderer.cpp`.
   - The scaffold instances are appended to the frame's instance buffer at an offset
     (`scaffoldBase`).
   - Its batches are drawn with `vkCmdDrawIndexed(range.indexCount, batch.count,
     range.firstIndex, range.vertexOffset, base + batch.first)`.
2. Do the same for `lab` with a `labBase`:
   - `ensureInstanceCapacity` must include `lab.size()`;
   - use the **opaque** pipeline (the one the main per-shape batches use, not
     `blendPipeline`). Glass parts may look wrong opaque. Accept that in §1 and note it;
     §2 revisits glass;
   - the draw range for each lab batch is `meshes_.labRanges[s]`, or
     `meshes_.ranges[Archetype::Cell]` for the Slab batch.
3. Draw the lab **before** the board's batches, so the depth buffer has the room first.
   That only matters for overdraw; correctness is the same either way.
